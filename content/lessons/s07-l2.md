## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **partition for access patterns** within files, formats, and partitioning.

## Build the mental model

Partition columns should match common filters and have manageable cardinality. Too many tiny partitions raise scheduling overhead; too few can force unnecessary reads.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.


## A mistake worth recognizing

> repartition changes the physical layout for a computation; it does not make a dataset permanently partitioned by itself.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
