# Aggregate at the right grain

## What you will be able to do

Compare employee counts with counts of recorded email addresses.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **aggregate at the right grain** within joins and aggregations.

## Build the mental model

Grouping defines the unit represented by each output row. Count rows, non-null values, or distinct entities according to the question. Join multiplication can inflate totals, so aggregate at the intended grain.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
from pyspark.sql import functions as F
result = people.groupBy("company_id").agg(F.count("name").alias("people"))
```

## A mistake worth recognizing

> count of a nullable column excludes null values; count of all rows does not.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
