# Named graphs and graph construction

## What you will be able to do

Build a normalized employer graph from one explicitly selected snapshot.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **named graphs and graph construction** within advanced sparql.

## Build the mental model

GRAPH chooses a named graph in a dataset. The default graph is not universally the union of named graphs. CONSTRUCT creates an RDF graph, so duplicate identical triples collapse even when underlying solution mappings repeat.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
CONSTRUCT { ?p ex:employer ?c } WHERE {
 GRAPH ex:snapshot { ?p ex:worksFor ?c }
}
```

## A mistake worth recognizing

> A named graph IRI does not by itself define who asserted its content or when.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
