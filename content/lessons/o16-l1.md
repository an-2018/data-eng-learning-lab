# Compatibility is behavioral

## What you will be able to do

Explain how a new disjointness axiom can break previously consistent data.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **compatibility is behavioral** within governance and release.

## Build the mental model

An ontology release can change query results, inferred types, or validation outcomes. Define compatibility in terms of consumer behavior. Test stored competency queries and constraints against representative old and new data.

## A mistake worth recognizing

> Adding an axiom is not always backward-compatible for reasoning or validation consumers.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

## Predict, then investigate

1. Explain how a new disjointness axiom can break previously consistent data.
2. Identify what happens when a relevant value or relationship is missing.
3. Change one fact or row and predict which part of the result changes.
4. Explain the result using the vocabulary introduced above.
