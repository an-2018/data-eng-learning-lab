# Duplicates are part of the result

## What you will be able to do

Compare counts of assignments and unique people using the same graph.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **duplicates are part of the result** within sparql composition.

## Build the mental model

SPARQL SELECT produces a multiset of solution mappings. Joins can multiply rows; DISTINCT removes duplicates across the projected variables. First inspect why duplicates exist, then decide whether removing them matches the question.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>

  ?assignment ex:person ?person ; ex:project ?project .
}
```

## A mistake worth recognizing

> Adding DISTINCT can hide a modeling or join mistake without repairing it.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
