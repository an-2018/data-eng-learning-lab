# Verify schema and multiplicity

## What you will be able to do

Design a test that distinguishes row counting from distinct-person counting.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **verify schema and multiplicity** within joins and aggregations.

## Build the mental model

DataFrame correctness includes schema and all row occurrences. Sorting is required only when an order contract exists. A robust test includes duplicates, unmatched keys, and empty inputs rather than checking a single happy-path sample.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
result = people.select("name").distinct()
```

## A mistake worth recognizing

> Using distinct to pass one fixture can remove legitimate repeated values in another.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
