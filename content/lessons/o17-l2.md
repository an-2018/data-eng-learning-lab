# Use selective constraints

## What you will be able to do

Identify a selective pattern and a pattern that can multiply rows.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **use selective constraints** within query optimization and benchmarking.

## Build the mental model

Exact identifiers, narrow graph scope, and constrained values can reduce intermediate bindings. The engine may reorder basic graph patterns, so textual order is not a physical-plan guarantee.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

## A mistake worth recognizing

> Moving a FILTER across OPTIONAL can change results even when it seems like a performance improvement.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

3. Change one fact or row and predict which part of the result changes.
