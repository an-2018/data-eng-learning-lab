# Bind expressions and constrain inputs

## What you will be able to do

Extend the query with another allowed person and predict which rows survive.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **bind expressions and constrain inputs** within sparql fundamentals.

## Build the mental model

BIND names an expression result. VALUES supplies explicit bindings and is useful for a small set of allowed identifiers. Keep computed labels separate from resource identity, and use parameterization rather than unsafe user-input concatenation.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?person ?nextYear WHERE {
  VALUES ?person { ex:ava ex:ben }
  ?person ex:years ?years .
  BIND(?years + 1 AS ?nextYear)
}
```

## A mistake worth recognizing

> A computed display string should not silently replace the original resource IRI.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
