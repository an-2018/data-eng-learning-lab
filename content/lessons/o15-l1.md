# Selectivity and cardinality

## What you will be able to do

Estimate intermediate rows for joining employees to every label in the graph.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **selectivity and cardinality** within query performance.

## Build the mental model

Selective patterns reduce candidate mappings. Join cardinality determines how much intermediate work is produced. Inspect the data distribution and execution plan rather than assuming the order written in the query is the physical order executed.

## A mistake worth recognizing

> Placing a selective pattern first in text does not force an optimizer to execute it first.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
