You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **running and moving calculations** within window functions and deterministic deduplication.

## Build the mental model

Window frames define which ordered rows contribute to an aggregate. A running total uses rows up to the current row; a moving calculation uses a bounded frame.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
from pyspark.sql import Window, functions as F
w = Window.partitionBy("company_id").orderBy("years").rowsBetween(Window.unboundedPreceding, Window.currentRow)
result = people.withColumn("running_years", F.sum("years").over(w))
```

## A mistake worth recognizing

> A grouped aggregate collapses rows; a window aggregate preserves them.
