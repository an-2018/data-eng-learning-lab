## What you will be able to do

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **set operations and schema compatibility** within spark sql and relational transformations.

## Build the mental model

UNION ALL preserves repeated rows while UNION removes duplicates. Both sides require compatible columns; make casts and aliases explicit instead of relying on positional coincidence.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
result = spark.sql("SELECT name FROM staff WHERE company_id = 1 UNION ALL SELECT name FROM staff WHERE company_id = 2")
```

## A mistake worth recognizing

> UNION is not a join and it does not match rows by key.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
