# Test the contract, not an implementation

## What you will be able to do

Write cases that distinguish a valid empty output from a failed transformation.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **test the contract, not an implementation** within testing and repeatable spark pipelines.

## Build the mental model

A Spark transformation is correct when its schema and row multiset meet the contract. Test empty inputs, nulls, duplicates, and unexpected values in addition to the happy path.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
result = people.filter("years >= 0").select("name", "years")
```

## A mistake worth recognizing

> A test that checks only row count can miss a type, nullability, or duplication error.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
