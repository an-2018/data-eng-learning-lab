## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **data quality and quarantine** within testing and repeatable spark pipelines.

## Build the mental model

Separate valid outputs from rows that fail a stated contract. Keep the original row, failure reason, source snapshot, and mapping version so the issue can be corrected and replayed.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
from pyspark.sql import functions as F
result = people.withColumn("is_valid", F.col("years").isNotNull() & (F.col("years") >= 0))
```

## A mistake worth recognizing
