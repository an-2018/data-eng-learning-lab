# Ranking, ties, and null ordering

## What you will be able to do

Compare row_number, rank, and dense_rank on tied values.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **ranking, ties, and null ordering** within window functions and deterministic deduplication.

## Build the mental model

row_number breaks ties by order position, rank leaves gaps after ties, and dense_rank does not. Null ordering is part of the contract and should be specified for production deduplication.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
from pyspark.sql import Window, functions as F
w = Window.partitionBy("company_id").orderBy(F.col("years").desc_nulls_last())
result = people.withColumn("rank", F.dense_rank().over(w))
```

## A mistake worth recognizing

> Ranking ties without a full ordering can make a chosen winner change across runs.
