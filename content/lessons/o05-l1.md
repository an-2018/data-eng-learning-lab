# Aggregation and subqueries

## What you will be able to do

Count employees per company, then explain the grouping key.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **aggregation and subqueries** within advanced sparql.

## Build the mental model

GROUP BY groups mappings before aggregates are computed. COUNT(*) counts rows; COUNT(?x) ignores unbound values; COUNT(DISTINCT ?x) counts distinct bound values. A subquery can establish a grouping level before later joins multiply results.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?company (COUNT(DISTINCT ?person) AS ?people) WHERE {
 ?person ex:worksFor ?company
} GROUP BY ?company
```

## A mistake worth recognizing

> A label join after grouping can still multiply output when labels have multiple languages.
