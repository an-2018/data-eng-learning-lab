# Pair search with graph evidence

## What you will be able to do

Design the link from a search hit to its resource and publication version.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **pair search with graph evidence** within dataset architecture, federation, and search.

## Build the mental model

A search index supports lexical discovery while the graph answers identity, provenance, and relationship questions. Version an index from published graph data and expose the indexed graph release.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?resource ?label WHERE { ?resource rdfs:label ?label }
```

## A mistake worth recognizing

> A text-search hit is not an RDF entailment or identity assertion.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

## Predict, then investigate

1. Design the link from a search hit to its resource and publication version.
2. Identify what happens when a relevant value or relationship is missing.
3. Change one fact or row and predict which part of the result changes.
4. Explain the result using the vocabulary introduced above.
