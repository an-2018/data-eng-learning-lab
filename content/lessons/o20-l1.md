# Define access boundaries

## What you will be able to do

Map each operational role to the minimum actions and data it needs.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **define access boundaries** within production governance, security, and incident response.

## Build the mental model

Use least-privilege read, write, publication, operations, and administration roles. Named-graph boundaries alone are not an authorization model.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.


## A mistake worth recognizing

> Hiding a graph name in a client is not access control.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
