# Data types and explicit casts

## What you will be able to do

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **data types and explicit casts** within dataframes and schemas.

## Build the mental model

Casting changes a column type under Spark SQL rules. Decide how malformed values should be handled and pin relevant SQL settings. A cast that yields null needs a quarantine or validation policy when the field is required.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
from pyspark.sql import functions as F
result = people.select(F.col("years").cast("long").alias("years"))
```

## A mistake worth recognizing

> Casting is not a substitute for deciding what invalid source values mean.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
