# Write a complete graph pattern

## What you will be able to do

Write a complete query from an empty editor for employees of Northstar.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **write a complete graph pattern** within sparql fundamentals.

## Build the mental model

A basic graph pattern joins triple patterns through shared variables. Start from the relationship needed by the question, then add patterns that connect it to names or categories. Every selected variable should have an intentional binding source.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?person ?company WHERE {
  ?person a ex:Person ; ex:worksFor ?company .
}
```

## A mistake worth recognizing

> Variables with different names do not join just because their values seem related.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
