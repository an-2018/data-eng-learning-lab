# Transactions and concurrent readers

## What you will be able to do

Explain how a reader should behave while a writer replaces a snapshot.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **transactions and concurrent readers** within triplestore operations.

## Build the mental model

A transaction defines a consistency boundary for a sequence of operations. Readers and writers follow the engine isolation model. Never have unrelated processes manipulate the same embedded storage files without the documented access protocol.

## A mistake worth recognizing

> File-level sharing of an embedded dataset is not a substitute for a supported server endpoint.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
