# Avoid accidental Cartesian products

## What you will be able to do

Construct a tiny fixture where a missing join produces six rows instead of two.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **avoid accidental cartesian products** within query performance.

## Build the mental model

Patterns without shared variables combine independently, multiplying solutions. Sometimes that is intentional, but usually a missing join variable is the cause. DISTINCT may reduce final output while leaving the expensive intermediate computation intact.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.


## A mistake worth recognizing

> Using ?employer in one pattern and ?company in the next can leave the intended join disconnected.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
