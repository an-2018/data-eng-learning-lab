# Filter values deliberately

## What you will be able to do

Query people with at least three years of experience and explain a missing years value.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **filter values deliberately** within sparql fundamentals.

## Build the mental model

FILTER keeps solution mappings for which an expression evaluates true. Numeric comparisons depend on compatible datatypes. A filter using an unbound variable generally produces an error for that mapping, which does not pass the filter.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?person WHERE {
  ?person ex:years ?years .
  FILTER(?years >= 3)
}
```

## A mistake worth recognizing

> The textual position of FILTER inside the same group is not a promise of earlier physical execution.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
