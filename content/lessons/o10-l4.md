# SPARQL constraints and scope

## What you will be able to do

Validate that an assignment end date is not before its start date.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **sparql constraints and scope** within advanced shacl.

## Build the mental model

A SHACL SPARQL constraint reports violating solutions, typically involving $this. Keep the intended data graph and validation scope clear. Prefer Core constraints when they express the requirement directly, and reserve custom queries for rules such as cross-field comparisons.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT $this WHERE {
 $this ex:start ?start ; ex:end ?end .
 FILTER(?end < ?start)
}
```

## A mistake worth recognizing

> A query returning valid nodes instead of violating nodes reverses the rule.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
