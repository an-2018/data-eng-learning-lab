# Validate graph-ready audience attributes

## What you will be able to do

Write a shape for one score-bearing GenreAffinity and explain its validation report.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **validate graph-ready audience attributes** within media audience knowledge graphs and shacl.

## Build the mental model

SHACL verifies the staged RDF contract after Spark schema and quality checks. Validate class links, score ranges, cardinality, datatype, and report focus nodes before publication.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

## A mistake worth recognizing

> A conforming Spark schema does not guarantee that an RDF mapping has the right IRI, class, or graph relationship.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

## Predict, then investigate

2. Identify what happens when a relevant value or relationship is missing.
3. Change one fact or row and predict which part of the result changes.
4. Explain the result using the vocabulary introduced above.
