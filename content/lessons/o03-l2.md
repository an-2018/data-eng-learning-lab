# Join through an association

## What you will be able to do

Explain which variable identifies the association and why it matters.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **join through an association** within sparql fundamentals.

## Build the mental model

An Assignment can connect a Person and Project while carrying its own role and allocation. Follow the association resource rather than inventing a direct edge that is absent from the data. Count what the question asks: people, assignments, or projects.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```sparql
PREFIX ex: <https://example.org/>
PREFIX rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?person ?project WHERE {
  ?a ex:person ?person ; ex:project ?project .
  ?project ex:client ex:acme .
}
```

## A mistake worth recognizing

> Two assignments for one person can legitimately create two result rows.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
