# Names, labels, and documentation

## What you will be able to do

Design a stable IRI and two labels for a department whose name changes.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **names, labels, and documentation** within rdfs and vocabulary design.

## Build the mental model

An IRI is an identifier, while rdfs:label provides a human-facing name. Labels can change or be translated without replacing the resource. Document intended usage, examples, and any assumptions about lifecycle.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```turtle
@prefix ex: <https://example.org/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
@prefix sh: <http://www.w3.org/ns/shacl#> .
ex:Person rdfs:label "Person"@en, "Pessoa"@pt ;
  rdfs:comment "A human represented in the workforce graph." .
```

## A mistake worth recognizing

> Matching labels do not establish identity between classes or individuals.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

## Predict, then investigate

1. Design a stable IRI and two labels for a department whose name changes.
2. Identify what happens when a relevant value or relationship is missing.
3. Change one fact or row and predict which part of the result changes.
4. Explain the result using the vocabulary introduced above.
