# Register and query temporary views

## What you will be able to do

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **register and query temporary views** within spark sql and relational transformations.

## Build the mental model

A DataFrame can be registered as a temporary view so Spark SQL and DataFrame code share the same logical plan. Use views for a clear relational expression, then inspect the output schema rather than assuming SQL types.

## Worked example

Read the example before running it. Identify the input facts or columns, the relationship being expressed, and the expected result.

```python
people.createOrReplaceTempView("staff")
result = spark.sql("SELECT company_id, count(*) AS people FROM staff GROUP BY company_id")
```

## A mistake worth recognizing

> A temporary view is scoped to the current Spark session; it is not a durable table.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
