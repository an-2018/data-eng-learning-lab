# Deterministic matching

## What you will be able to do

Build a conflict case with the same email but incompatible employee identifiers.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **deterministic matching** within semantic integration and entity resolution.

## Build the mental model

A deterministic rule matches records using explicit conditions. A strong identifier still needs scope and lifecycle: an employee number may be unique only within a company. Detect conflicting evidence before accepting a merge.

## A mistake worth recognizing

> Matching email alone can merge shared mailboxes or reassigned accounts.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.
