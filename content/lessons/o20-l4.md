# Govern change and deprecation

## What you will be able to do

Plan a compatible replacement for a deprecated predicate.

## The problem

You are working with workforce and project data that will be used by another team. Your result must have a clear meaning, survive incomplete records, and be reproducible. This lesson focuses on **govern change and deprecation** within production governance, security, and incident response.

## Build the mental model

Review compatibility, mapping impacts, validation, query behavior, access effects, and rollback. Deprecate terms with migration guidance and retain historical versions when required.

## A mistake worth recognizing

> Changing an IRI meaning without migration can silently break historical queries.

Construct a small counterexample that would expose this mistake. Prefer three carefully chosen records to a large dataset whose behavior is hard to explain.

2. Identify what happens when a relevant value or relationship is missing.
3. Change one fact or row and predict which part of the result changes.
4. Explain the result using the vocabulary introduced above.
